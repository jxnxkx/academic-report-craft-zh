# 术语和证据

## 一、同一对象保持同名

需要的是稳定的对象映射，不是盲目全文替换。

遇到多个名称时，先区分：

| 名称关系 | 处理方法 |
| --- | --- |
| 同一对象的随意近义称呼 | 选择已确认名称，统一相关位置 |
| 同一对象在不同层级的称呼 | 定义关系，如模型与模型服务，不强制只留一个词 |
| 不同对象被写成同一个词 | 补足限定，如真实状态、系统观测、状态估计 |
| 标准术语与项目内部字段 | 正文使用可理解的术语，代码字段仅在实现需要时出现 |
| 图中简称与正文全称 | 建立一次明确对应，不用大量“为排版故改名”的元说明 |

用户确认的名称优先于助手临时创造的漂亮词。新名称只有在确实提高准确性和可读性时才值得提出。

### 名称检查的五个问题

1. 它指向哪个人、模型、数据对象、动作或指标？
2. 读者第一次看到是否知道大致做什么？
3. 它是否已经有领域通行名称？
4. 它会不会让读者误以为多了一个模型或算法？
5. 改名后是否改变比较条件或技术含义？

“证据账本”改为“证据记录”，解决的是自造比喻；“语义模型服务”改为“自然语言处理服务”，解决的是职责难识别。后期若模型职责和命名进一步调整，以新稿为准，不能把这两组历史替换作为所有项目的永久字典。

## 二、学术概念不等于代码标签

报告里的状态、动作、奖励、损失和评价指标，需要先有明确对象和关系，再选择名称。

- `optimizer.step`可以在实际以优化器更新为单位时称“参数更新次数”，但不是样本数、问答轮数或累计反向传播次数。
- `should_finish`可以解释为结束判断，不能因字段存在就认定实验评价了自主停止。
- `item_state_f1`等内部名不能直接翻译成看似标准的“严格证据F1”，须核对它实际比较什么。
- “测量反馈训练”和“完整访谈反馈训练”若只是同一训练算法中少一个奖励项，应写清奖励设置，不让名称暗示两套方法。

检索通行术语适用于存在概念疑问的时候。普通措辞替换不需要每次检索论文，更不需要启动服务器训练审计。

### 首次出现与简称

对后文反复使用且读者需要识别的专业概念，首次出现默认写“中文名称（English Full Name, ABBR）”，例如“主成分分析（Principal Component Analysis, PCA）”。外侧采用中文全角括号`（）`；英文全称与缩写之间采用英文半角逗号加一个半角空格`, `；括号内两端不额外加空格，中文名称与左括号之间不加空格。已在前文定义的对象不必反复展开。

不要为普通中文职责补造英文全称或缩写；也不要为了避免英文，把Transformer、LoRA等名称改成读者无法识别的译名。英文全称的拼写、大小写和缩写采用该术语的通行形式，不因示例而将所有英文强制改成标题式大写。上述括号与逗号规则仅用于中文术语的英文全称和缩写释义，不用于数学公式、代码或文献原题名；有明确模板或用户另行指定的格式时按该要求执行。

## 三、方法介绍中的边界

### 理论来源与项目映射分开

先说明标准模型包含什么，再说明本项目如何对应和采用。状态估计、完整信念分布、结构化信息状态不是天然同义词；一个图中画了POMDP字样也不能代替数学定义。

知识蒸馏、普通监督微调、硬标签学习和软分布匹配也不能靠语言包装混为一谈。介绍实际输入、目标和损失，比泛称“对比学习”更可靠。

### 已设计、已实现、已验证分开

系统设计可直接写“系统采用……”。完成实现可以写“程序能够……”。实测比较才能写“结果提高……”。

历史数据处理管道可以是持续迭代设计，但若当前训练只用了仿真数据，不得因为管道存在就说当前结果来自真实使用记录。相反，后续确已使用并有材料支持时，也不要被旧稿限制为“尚未”。

这些区别以当前材料为准。本Skill不冻结原项目的任何模型版本、训练数据来源或奖励项。

## 四、指标定义

使用自定义指标前，至少能够说明以下信息；这些信息可写在正文、公式或表注中，不必另建一张“合同表”：

- 统计对象是什么：题目、证据、轮次、会话还是模型版本。
- 分子与分母是什么，什么时候纳入或排除。
- 统计时点或范围是什么。
- 数值范围、单位及好坏方向。
- 多个样本如何汇总，是先逐样本计算再平均，还是汇总计数后计算。
- 无样本、分母为零、提前结束等情况如何处理，如果这些情况会影响解释。

例如“已经可计分的题目占全部题目的比例”和“可计分题目中判断正确的比例”分母不同，不能为了表头简短合称“测量准确率”。“没有新证据”也不必然等于“没有推进”，因为澄清冲突或修正错误可能构成推进。

通行的精确率、召回率、F1仍要指出匹配的对象。不要默认某个项目的字符级匹配、题目级匹配与来源轮次匹配可互换。

## 五、公式和符号

公式的作用是精确表达对象关系或计算过程，不是增加篇幅。

### 写公式前

- 检查该关系是否需要数学表达；简单功能列表不必数学化。
- 优先沿用本章和相应方法文献的惯例。没有唯一惯例时可以自定义，但应完整说明，不宣称“官方必须如此”。
- 区分时间索引、样本索引、集合、模型参数、状态、观测和动作，不复用同一个符号表达无关对象。
- 检查动作和观测的时序：当前观测形成何时的状态，当前动作之后出现何时的新观测。

### 独立计算逐式解释

连续介绍几个独立计算步骤时，采用用户确认的顺序：引出这一步 → 独立公式并编号 → 紧接“其中，……”解释 → 承接前一步结果，再引出下一式。不要先堆放多条公式，最后用一大段统一解释。

“紧接”指内容顺序，不要求强制同页。Word文档按[自然分页偏好](revision-and-delivery.md)处理，不为公式和释义自动添加“与下段同页”或“段中不分页”。

- 独立成行的公式原则上一行只表达一个主要关系；几个独立定义用逗号并排时，应拆开并分别解释。集合元素、函数参数中的逗号不作为拆式依据。
- 例如“得分占比 → 信息熵 → 熵权”承担三个计算步骤，可以分别编号、分别释义，并说明后一步如何使用前一步的结果。
- “其中”解释首次出现或在此承担特殊含义的符号、单位、条件及该式的计算含义，顺序尽量对应公式。相邻公式已定义的符号可以沿用，不必反复释义，也不把每个求和号和加减号逐一翻译。
- 拆式或合并后，同步检查编号与正文引用；不让下一式沿用原来已经指向另一关系的编号。
- 独立计算式拆开后默认按当前章连续编号，例如（4.6）、（4.7）、（4.8），不使用（4.6a）至（4.6c）代替顺序编号。不同项目有明确模板规定时按该项目执行。
- 公式排法：
  1. 尽量避免行内出现多行公式。
  2. 对于行外公式（居中放置），如果包含两行，尽量拆开。
  3. 如果拆开的两行公式是递进关系，需在两个公式之间添加“其中”等说明，以解释推导过程，并补充必要的介绍。
  
  例：“*E*(*t*) = *P*<sub>LV</sub>(*t*)/(*V*<sub>LV</sub>(*t*) − *V*<sub>0</sub>)”与“*P*<sub>LV,es</sub> = *E*<sub>max</sub>(*V*<sub>LV,es</sub> − *V*<sub>0</sub>)”原来上下合排在一个公式里。前式定义时变弹性，后式用取到的收缩末期点作线性拟合，是递进关系，应拆成两式，中间说明“取各环时变弹性最大值对应的点作为收缩末期点”，再引出拟合式。
- 引出独立公式的句子统一以冒号结束，“满足”“表示为”“如下”后都加“：”，不让同一文档里有的加、有的不加。
- “其中，……”解释段顶格，不作首行缩进。解释和引出下一式的文字较短、内容紧密相接时，合为一段；不要让“根据……计算……”单独占一个短段。独立计算式仍各自编号、紧随释义，不因此合回一组公式。

### 前式的简单性质放进说明

如果后一行只是前一公式直接得到的归一性等简单性质，没有新增计算步骤或独立建模作用，将其写入前式后的“其中”段。可用文字或行内公式说明，不再为这条性质另起独立公式或编号。

用户确认的例子：组合权重的归一化公式单独列出并编号。原来紧随其后的 $\sum_{j=1}^{m}w_j=1$ 并入说明：

> 其中，……。分母为全部指标几何平均权重之和，归一化后，各指标权重之和为1。

需要保留数学表达时，可在该段写“归一化后，各指标权重满足 $\sum_{j=1}^{m}w_j=1$”。两种写法按上下文选择，不重复列出同一性质。

先判断数学作用，再决定排法。优化问题的可行域约束、需要单独论证的命题或具有独立引用作用的关系仍可独立列式；不能仅因为外形是“和等于1”，就一律降为行内说明。分段函数、联立方程和共同定义可行域的约束组必须一起读，可保留合排，不机械地按等号拆开；除此之外的两行公式，按上文“公式排法”第2条尽量拆开。这是用户的叙述偏好，不声称为赛事或学术排版的统一规定。

### 符号与转换核对

拆式和转换均保留原有数学含义：核对上下标作用对象、分式和根号覆盖范围、求和范围及括号类型。区分源码分组用的花括号与需要显示的集合括号；不能只凭转换成功就认定符号正确。

变量用数学斜体，单位和说明性下标用正体，细则见下方[符号正斜体](#符号正斜体)；工具层面以用户指定的MathType、Office公式或LaTeX工作流为准。用户要求交付`$...$`原文时不擅自转成Word公式，普通Markdown也不自动沿用只适合其当时转换工具的单美元块公式做法。

从DOCX提取文本若未识别MathType/OLE公式，不能据此认定源文档公式为空。需查看实际渲染或公式对象后再判断。

用户指定 MathType 并要求单行斜线分式时，使用原生同基线斜线分式和自适应括号模板，让符号随内容伸展，不用手工放大字号补偿普通字符。具体转换和核验见[MathType 公式排版](mathtype-formatting.md)。这不要求所有分式改成斜线形式。

### 符号正斜体

以下规则适用于正文、PPT、图中文字和公式，避免同一符号在公式里是斜体、在正文里却是正体：

| 类别 | 字体 | 例 |
| --- | --- | --- |
| 变量、物理量、函数符号 | 斜体 | *L*、*J*、*α*、*S*、*U*、*H*；网络符号 *F*、*G*、*C* |
| 数字 | 正体 | 2、0.5 |
| 单位 | 正体 | dB、Hz、mmHg |
| 缩写、方法名、数据集名 | 正体 | CNN、PI、IUKF、RML2016.10a |
| 说明性下标（文字或编号） | 正体 | *C*₀ 的 0，*L*<sub>cls</sub> 的 cls，*R*<sub>AVP</sub> 的 AVP |
| 变量下标 | 斜体 | *x*<sub>*i*</sub> 的 *i*，*e*<sub>*t*</sub> 的 *t* |
| 运算符 | 正体 | =、+、→、≈ |

拉丁字母和希腊字母（如 *α*、*θ*）用 Times New Roman，不落到中文字体上。依据是本Skill“变量用数学斜体”的原则和GB 3102的通行做法。

新增或修改含符号的内容后扫一遍：Word或PowerPoint中前后都不是字母、却为正体的单个拉丁或希腊字母多半是漏改；图片里的符号（Visio、matplotlib）也要查。

## 六、结论与证据对齐

| 证据 | 可以直接支持的表述 | 不能单凭它推出 |
| --- | --- | --- |
| 功能请求成功 | 该流程完成运行或联调 | 稳定性能、全部场景可用 |
| 参数量降低 | 该模块规模更小 | 能力无损、全系统只有该参数量 |
| 固定预算下题目数增加 | 信息采集推进更快 | 得分更准确、真人负担降低 |
| 准确性和推进共同改善 | 指定任务下结果与过程改善 | 未测人群或临床有效性 |
| 一个奖励条件优于另一个 | 相同条件下的观察差异 | 未控制因素之外的独立因果解释 |
| 医院部署和试用 | 有实际应用环境和流程工作 | 完成临床验证、省内或全国首创 |

避免未经检验的“显著”，有统计检验时再按实际结果报告。原因解释可用“这与……一致”“可能与……有关”，但不要把推测写成已经测出的机制。

百分比由72.3%升到79.2%，是提高6.9个百分点；相对提升另用差值除以原值。表格外的数值与附件编号范围默认写“至”，例如“67%至98%”“A4至A15”；保留端点、单位和原有精度，不把确定精度数据一概模糊化。其他横线的辨认与表格例外见[范围和横线](sentence-and-paragraph.md#范围和横线)。

## 七、引用与来源

正文引用紧随受支持的判断；不同研究分别支持不同分句时，不将一串编号堆在整段末尾让关系不清。理论、量表和算法应优先找原始论文或标准；政策、规则和现行型号要查相应一手资料。

文献支撑“这种方法存在”不等于支撑“本项目已经有效”。同样，作者对某理论的通俗描述不能替代该理论本身。

### 文献来源选择

参考文献优先选用正式发表的期刊论文和会议论文，优先引用实际所用方法的原始论文。不按数量凑文献，也不为满足文献类型偏好引用不能支持当前论断的文章。

- 同一工作已有正式发表版本时，优先采用该版本，并核对正式题名、作者、会议或期刊、年份及页码；不能把预印本题名与另一版本的出版信息混拼。仅有预印本时如实标注；若现有正式论文已充分支持该处且预印本没有独立作用，可删去冗余引用。
- 赛题、附件说明、项目内部材料不作为补足学术文献数量的条目。已有正文确需保留的数据或软件来源名称可保留；原文没有相应来源说明时，不为安置删除的书目新增“数据来源”章节、段落、脚注或附录。不能把本已明确的题定条件包装成外部研究依据。
- 必要的标准、专著及官方技术文档可以保留，但应能对应具体论述。方法首次系统提出于专著，或公式与实现细节只能由官方文档准确支持时，不用一篇宽泛综述或软件介绍论文硬替换；重复支撑同一事实的非论文来源可精简。
- 审查和删除书目时，同步核对全文引用。相关事实仍成立且不依赖该书目时，只去掉标号；只有确认另一文献直接支持同一论断时才转引。不得给仍需依据的论断随意换号。完成有实质增删的全文审查后，按正文首次引用顺序重排，并检查悬空引用、漏引条目、重复条目及上标格式。

这是本Skill的选材偏好，不声称期刊、赛事或GB/T标准禁止引用其他类型资料；当前任务要求或必要出处优先。来源取舍、替换依据与待核验事项放入独立修改记录，不为了展示审查过程扩写论文正文。

### 默认参考文献格式

无另行指定的模板、赛事或投稿要求时，**参照GB/T 7714—2025顺序编码制，采用简化著录**。这是本Skill的默认写作设置。

著者、题名和编号缩进三项参照了同一课题组已提交的开题报告和学位论文。全大写姓氏是GB/T 7714标准示例采用的写法，并不错误；这里选择与课题组已提交的报告保持一致，使用时可按所在单位的惯例调整。旧稿改为此格式时，只改大小写、空格和段落格式，不改动著录内容和编号顺序。

已有文稿只做格式升级时，保留现有编号及正文对应关系，除非本轮明确要求重新排序；历史上“中文文献放在前五条”的安排不作为新稿默认排序。删除URL也不应把预印本编号、文章编号或题名中的必要字符一并删去。

在Word等支持字符格式的文档中应用真实上标格式；纯文本或未配置上标渲染的Markdown先保留完整的方括号编号，并在导出时应用上标，不替换成含义不清的Unicode拼接。上标规则仅针对文献引用，不改变图号、表号、公式编号或一般数字。

明确的模板或投稿要求优先于上述默认值；例如对方要求完整在线资源信息时，应保留相应字段。该默认设置只在本轮包含参考文献撰写或格式处理时执行，不因普通段落润色而自动重排全文。

## 八、必要核查的尺度

普通润色：保持事实，修语言即可。

发现局部冲突：查与该处直接相关的定义或图表；仍不清楚时提出一个具体问题。

新增算法、奖励或效果主张：需要相应来源，缺少时标记待确认。

用户明确要求代码审计、公式核对或文献核验时，再开展相应专项工作。不得把“换几个名称”升级为训练器全链路验证。
