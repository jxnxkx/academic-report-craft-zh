# 协作和交付

## 一、先辨认这轮究竟要做什么

| 用户请求 | 合适的响应 | 不要自动扩展成 |
| --- | --- | --- |
| “先看一下”“先别改”“给大纲” | 分析、定位问题或给结构 | 写入源文件 |
| “这段重写” | 给出替换段落，保留相关定义 | 全章重构、改标题 |
| “原封不动写进去” | 原文插入，必要格式沿用 | 润色、补论证、改术语 |
| “统一成这个名称” | 在授权范围准确替换并核对 | 新概念设计、训练代码审计 |
| “图片改好了” | 替换指定图片，保留位置和尺寸 | 重画图、改变数据 |
| “新开v8，不升级v9” | 按明确版本名交付 | 自行另起版本 |
| “只给Visio地址” | 交付可编辑Visio及路径 | 插入Word、额外改稿 |
| “按讨论整理写作风格” | 抽取稳定取舍并说明来源 | 将所有助手提议写成硬规则 |

小任务可以直接处理，不要求每次长篇计划或反复确认。会改变论证方向、事实含义或既有交付时再明确说明。

## 二、基线与冻结内容

用户手动修改后的最新文件是基线，不拿旧导出稿覆盖。文件名可能仍是同一版本号，不能单凭版本号判断内容新旧。

“暂时冻结”意味着后续只处理相关新增问题，不因发现另一种写法就重开全段。“标题已调好，不许动”应作为局部不可改范围保留。

当用户在逐句讨论时，只推进当前句段；用户要求全文成稿时，直接把已确认内容整理完整，不继续模拟每句话都要审批的流程。

## 三、内容检查不等于重新验证整个项目

本风格提倡证据清楚，但写作编辑不是每次重新跑实验。

例如“测量反馈训练”改名为“仅使用测量奖励”时，若只是已有定义下的措辞替换，就做文字和图表同步；若文本还新增“奖励包括停止偏差”，而现有材料未确认，指出该项需要依据。不要连带启动服务器、优化器和全训练链路审计。

用户明确要求审计时再开展专项核查。用户说没有时间、不处理训练时，停止扩张核查范围，完成已授权的文字工作，并把尚未确认之处简明标出。

## 四、文本统一的范围

替换前确定目标对象。例如“本文方法”到“本项目方法”可以覆盖正文、表格和题注中指代本项目的地方；不能将引用论文中的“本文”或普通词组里的“方法”无差别替换。

文字层、图片层和公式层分开处理：

- 可编辑正文、表格、题注：在授权范围直接替换。
- 图片里的旧字：若用户负责重画，保留并告知，不伪称已经同步。
- 文献题名、代码标识和原文引用：默认保持原貌，除非用户明确要求处理。
- 公式符号：不靠全局文本替换改变量名。

替换后检查同一对象是否仍有其他旧称，以及替换是否造成重复、搭配不自然或事实变化。只报告有意义的遗留项。

执行[横线统一规则](sentence-and-paragraph.md#范围和横线)时，先排除表格内部文字，表格外的表题仍纳入；不要对全部横线字符作无差别替换。原文修改保留所在章节及修改前后的Markdown对照，公式、负号和代码标识单独保护。

## 五、编辑文件时保护原有成果

实际修改Word、PPT或Visio前使用可回退备份；尊重正在打开的文件和用户未保存的修改。具体编辑和渲染使用相应文件工具或技能，不靠写作Skill自行规定低层文件操作。

只改内容时，不调整行距、分页、页码、表格边框、字号和图片比例。插入造成版面变化可以告知，不自动为追求页数去压缩全文行距。

修改后做与范围相称的检查：文字替换检查遗漏和误替换；插图检查位置与显示；公式检查符号及实际渲染。不要宣称没有进行的视觉检查或实验验证。

交付说明应包含文件位置及本轮改了什么。备份位置可在需要时提供，不把中间脚本、日志和几十个处理步骤当成主要成果。

## 六、格式按项目确认，不沿用反复变动的旧命令

历史讨论中，下列要求曾调整或只针对某次交付：

- 英文、数字与中文之间是否留空格。
- 按章节编号还是全文连续编号。
- 图分成独立图还是多个子图。
- 公式输出为LaTeX原文还是可编辑公式对象。
- 新修改是否加粗，是否需要另存版本。

遇到这些问题，先看当前用户要求和模板，不能把某一条历史要求提升为永远适用的写作规则。改稿过程中新增的加粗通常用于标识修改，不自动当成最终正文的强调风格。

参考文献是例外：GB/T 7714—2025顺序编码制的约定简化格式、正文引用上标和文后两端对齐是本Skill的默认设置，具体执行[术语和证据](terminology-and-evidence.md)第七节。没有新要求时不必反复询问，但不得超出本轮编辑范围修改既有文档。

### 正文中文字体

无另行指定的模板要求时，正文中文及中文标点采用宋体，中文双引号`“”`也随正文使用宋体，不因邻接英文而切换到西文字体。应用到Word时核对引号和中文标点的实际字体，不只看整段的概括显示。此默认值不自行指定字号，也不将标题、英文、数字、公式或MathType对象一并改成宋体；这些沿用项目已确认格式。只更新Skill或局部润色时，不据此修改文稿的字体。

术语首次出现的括号、逗号和空格采用[首次出现与简称](terminology-and-evidence.md#首次出现与简称)的默认写法。

### 含行内公式的正文行距

如果套用之前的模板，且模板以可读性为主（1.25倍行距和20磅固定值视觉效果相近），建议直接用20磅行间距，以避免公式导致段内行距不一致。

原因是倍数行距下，含 MathType 等行内公式对象的行会被撑高，整页行距忽大忽小。改为固定值20磅时，插图段落和独立公式段落不用固定值，否则图片和公式会被截掉，保持单倍行距；改完放大查看带下标的行，确认没有被截。模板对行距有明确要求时以模板为准；只做局部润色时，不据此改动全文行距。

### Word文档的自然分页偏好

Word段落默认采用普通正文的自然分页，不自动启用“与下段同页”（keep-with-next / `keepNext`）；公式和释义也不额外启用“段中不分页”（keep-lines-together / `keepLines`）。不得因为公式与解释在叙述上紧接，就额外添加这些分页保护。用户明确要求清除时，在授权范围内同时核对段落直接格式与继承样式，避免清除直接设置后仍由样式启用。

这里的“普通正文”指自然分页行为。保留文字、公式、编号、字体、标题层级及明确的章节分页，不把全文或标题统一套成Normal样式；不为消除左侧非打印标记而删除显式分页符、分节符或明确的章前分页。

这项偏好取代了早先“只隐藏标记、保留分页保护”的建议，理由见[设计依据](design-rationale.md)。仅做文字润色而未授权调整分页时，仍遵守本文件第五节的范围限制；后续用户另有明确排版要求时，以新要求为准。

## 七、讨论稿、正文和内部记录分开

讨论可以使用列表、表格、口语例子和“这一段要回答什么”；正式正文不包含这些编辑说明。

应清除或移出正文的例子：

- “这版可以写入正文。”
- “本次修改统一了模型分工。”
- “当前稿已经列为工程实现组成。”
- “为了适应图中版面，所以这几个词换成简称。”
- 仍未处理的模型待填值和结果编写提醒。

这不表示正式文档禁止方法解释或简称定义，而是不要让读者读到编辑过程。

## 八、对用户的表达

用户要替换文本时，先给可用文本，不用长篇夸赞“这次终于清楚了”。解释应聚焦实际变化，如对象明确了、删去无指向限定、统一了条件名称。

不要用另一个抽象体系解释用户抱怨的抽象。可以先用一句普通话确认意思，再给正式写法。

较大工作需说明正在检查什么及找到的具体问题，不反复承诺“马上完成”而没有产物。确认已完成时只报告真正完成的部分。
