# 图表和汇报

## 一、先确定图要回答什么

图不是越多越能说明工作量。创建或保留一张图前，用一句话说清它提供了正文和其他图没有清楚呈现的关系。

| 图的类型 | 核心问题 | 常见过载 |
| --- | --- | --- |
| 整体目标图 | 项目要完成哪些工作，形成什么结果 | 只画算法创新，漏掉整个系统 |
| 总体架构图 | 组件是什么，各自负责什么 | 同时塞入每轮执行步骤和训练细节 |
| 运行流程图 | 谁先处理什么，数据怎样流动 | 把模块包含关系误画成先后顺序 |
| 方法图 | 哪个机制解决哪个具体问题 | 第二章与第三章重复同一条箭头链 |
| 部署图 | 设备和程序装在哪里，输入输出到哪里 | 加入奖励项、检查点和全部模型型号 |
| 数据图 | 数据的组成或组织单位是什么 | 色块没有单位，样本数含义不清 |
| 结果图 | 条件之间或过程之中发生了什么变化 | 与结果表完全重复，轴名只有“指标值” |
| 系统截图 | 某角色在此完成什么实际动作 | 用静态页面数值证明正式实验效果 |

例如“方法原理图”和“训练实施图”若只有最后几个保存/接纳节点不同，可能只需保留一张，另一处回指并用正文补充实施。

## 二、图前引入与图后分析

按句子的功能选词，不能把“可知”和“所示”按图的上下位置机械绑定。

- 引出对象：`系统部署关系如图9所示。`
- 报告观察：`由图6可知，在相同轮次下，本项目方法获得了更多可计分题目。`
- 解释趋势：`两条曲线的差距在第4轮后逐渐扩大。`
- 回到问题：`该结果表明，状态驱动的目标选择有助于在固定预算内推进信息采集。`

正文引用图时写“如图5(a)所示”或“图6(b)所示的……模型”，不在句中夹“（图5(a)）”这样的括号。括号既打断句子，又容易与引用号混在一起：“采用闭环心血管电路模型（图8）[41]”应改为“采用闭环心血管电路模型[41]，其结构如图8所示”，让引用号紧跟它的出处。“图4为……的结果”一类也改成“……的结果如图4所示”，全文统一。

历史讨论一度要求“可知在前、所示在后”，但最终稿实际采用“如图所示”引入、“由图可知”分析。长期风格继承其明确指引和分析的意图，不将那次位置口令当语法规范。若用户在当前任务再次明确指定用法，按其具体要求处理，不偷偷改回。

表格同理：表前说明比较什么或记录什么，表后说明重要差异；不是每张表都要补一大段解释。

### 不复述整张图

图后重点说明结构中的关键关系、曲线中的重要变化或结果对应的研究判断。正文不逐个念模块名；对于只能通过文字解释的条件、统计单位或歧义，必须写清。

没有数据时可先写展示对象和轴的含义，不能预判曲线“显著上升”。结果更新后要同步修改图后描述，不能只换图片。

## 三、短标签与完整解释分工

图内标签要能脱离正文大致看懂，正文解释细节。缩短名称应保留核心对象，不把“自然语言回复”缩成含义不清的“自然回复”，也不把“当前访谈状态”随意换成另一个理论术语。

框内名称、图例、表中条件与正文使用同一组称呼。若用户确认“监督微调基线、不含交互质量奖励、包含交互质量奖励”，相关描述应同步，不能让正文继续使用旧的两套“反馈训练”名称。

图中的一个框表示模块、数据对象还是使用角色，要保持层级清楚。箭头表示调用、传递、先后还是反馈也应有确定含义；语义不成立的长连线不能仅为画面对称保留。

用户偏好普通矩形或小圆角矩形、紧凑对齐和清楚的连线，不偏好胶囊框、大量悬浮注释及纯装饰。仍须服从当前图稿，不自动重画所有图。

## 四、图表选择和版面

### 图与表的取舍

少量离散指标需要精确比较时，表格通常更直接；逐轮增长、训练变化等连续趋势适合曲线。不要给每一项指标强制生成一张图。

表头保留对象和单位，把长计算定义放正文。文字需要多行时自然换行，不能为了表头工整发明难懂的简称。历史上“最多两三行”是特定Word栏宽下的考虑，不是所有表格的法则。

数据矩阵和占比图组合前必须知道每个小框、色块、行列及灰色区域的统计含义。`n`可能指会话、动作样本或目标数，不能根据图形猜。

### 可读性比组合形式优先

复杂界面截图和纵轴不同的实验图，缩成2×2可能看不清，可以分别全宽放置。两幅讲同一数据构成的图也可以组成上下排列的子图。用户不是永久禁止组合图，而是在相应内容下优先保证可读性。

字体大小、边距和图形比例按插入后的实际可读性决定，不强套16:9，也不从历史截图复制某个字号。中文宋体、英文和数字Times New Roman是该项目多次确认的图中文字偏好；新项目如有模板或用户要求，以当前要求为准。

用程序画的图（matplotlib、plotly等）默认是思源黑体、DejaVu Sans一类无衬线字体，读者一眼就能看出是程序直接生成的。交付前统一改成与正文一致的宋体加Times New Roman，字号按插入Word后的实际尺寸取小五号（9 pt）左右，子图说明“(a) ……”同样处理；变量按[符号正斜体](terminology-and-evidence.md#符号正斜体)写成斜体。只有位图、没有源程序时，柱状图按图上标注的数值重画，曲线从像素中取点重画，照片、仿真截图和文献示意图保留原图，只重排坐标轴和文字，不改动数据。具体做法见 `word-office-automation` Skill 的[图中文字重排](../../word-office-automation/references/figure-text-redraw.md)。

图题通常放在正文外部题注，不在图片中再写一次大标题。图例、刻度、轴标题和说明不能相互覆盖。

### 误差带与数据诚实性

误差棒、置信带需要明确的统计来源和含义，不能为“科研感”添加。用户曾因陌生而要求去掉误差棒，这不是统计图普遍不应有误差棒的证据。需要表达不确定性时应选择可解释的形式，并说明其含义。

纵轴可以采用0至1或百分比，但数据、刻度和轴标签必须一致；避免刻度百分号与轴单位用法含混。图中估读值不能冒充原始结果精度。

## 五、编号与格式属于当前项目配置

原项目后期确认的题注形式是`图1 标题`、`表1 标题`，数字前无空格、数字后一个空格，全文顺排。初期的`图3-4`等章节编号不再套回后期稿。

新项目不自动继承这个编号方案。新增图后同步题注、正文引用及图目录；只有用户授权时才进行全文编号更新。不可为了刷新题注同时改变页码字段、页眉或分节。

三线表线宽、行距、字号、图片宽度等以当前模板或专用文档规范为准。本Skill不提供一个从历史任务猜出的通用线宽。

## 六、由报告转成PPT和口播

### 保留事实主线，改变信息密度

报告负责完整论证，PPT通过关键图表组织展示，口播负责告诉观众此刻看什么及最重要的判断。不能简单将整段正文贴到PPT再逐字朗读。

总体展示页可以只说“如图一所示，是本项目系统的总体示意图”，不强制每页展开方法。结果页才用一两句指出比较所得；真人演示页说明实际操作与产物。

分节可从题目两部分或实际叙事任务展开，但不能为凑四部分临时制造新的研究对象。

### 口播是独立冻结稿

已经录制或确认的台词属于冻结内容。用户只要求更新Markdown时，保留原话、角色称呼和操作顺序；不因为认为更自然就改写已录制句子。

估时优先用本人实测语速，分别计算口播、系统语音、操作等待及转场。历史稿中的每秒字数和4.5秒等待只是当次参数，不成为今后所有视频的模板。

展示剪去了中间轮次时，使用清楚的省略过渡，不能使观众误以为三轮就完成了完整测评。演示素材和正式实验结果各有用途，旁白不要把前者当成后者。

### 页面名称和讲稿同步

检查页号、图号、条件名称、标题与实际画面。已录音部分需要更名时，先报告会影响哪段录音，不一边重排页面一边继续沿用旧稿。
