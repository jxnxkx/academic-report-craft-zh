# 设计依据

这份文件说明本Skill的规则从哪里来、为什么这样定。写作时不必通读；修改本Skill，或两条规则看起来冲突时再查。

## 一、材料与提炼方法

规则主要来自两部分材料：

- 一份研究生竞赛项目报告的逐句修改讨论，约两千条消息，去重后保留七百余条，其中用户消息三百余条；以及最终提交稿。
- 后续开题报告、学位论文相关文档的写作和排版，以及帮他人修改报告时形成的确认。

一条做法是否写成规则，按证据的用途判断，而不只看谁说过：

1. 作者多次明确修正、后来一直沿用的，作为稳定偏好。
2. 作者认可某次表述、最终稿也延续了的，作为可迁移的写法。
3. 助手提出、作者没有确认的，只作讨论背景，不形成要求。
4. 同一事项反复变动的，按最新任务和最终稿处理局部选择，不提升为通用规范。
5. 最终稿里有、但与明确偏好矛盾或属于残留错误的，不因为是“最终稿”就照抄。

例如“名词不要抽象”“同一对象保持同名”是稳定要求；“必须四张结果图”“所有图全宽”“单美元公式”都曾随阶段改变，不作为永久约束。

## 二、稳定写作选择

| 规则 | 依据 |
| --- | --- |
| 段首交代段落任务，句式可以变化 | 多次修改段首，最终稿分别以判断、条件、过程、成本问题起段 |
| 相邻段落复现同一个关键对象 | 只靠“因此”衔接时，读者要自己补一层概念关系 |
| 理论篇幅围绕项目需要取舍 | 通用架构介绍被压缩，转向项目真正用到的部分 |
| 不反对真实并列，反对空洞的概念串 | 保留明确的组件、阶段和条件，不设“禁止顿号”之类的词表 |
| 第一眼能知道名称指什么；同一对象名称统一 | 反复出现“名称从代码字段拼出来”“图和正文叫法不一”的问题 |
| 让执行动作的主体出现 | 系统、程序、模型、人员各自做了什么要写清 |
| 限定词会增加解释责任 | “可控、稳定、鲁棒”等按实际含义使用，不是绝对禁词 |
| 技术章节不是数据生产日志 | 作者明确要求正文讲原理、流程和结果，不讲排障过程 |
| 方法和实验从同一问题出发；指标必须能解释和计算 | 实验名称要暴露真正改变的条件，例如“是否加入某项奖励” |
| 完成的工作明确写出，不反复自我削弱 | 用部署、联调、试用等动作展示成果，关键边界说准一次 |
| 已录制或已确认的台词不擅改；最新手动稿优先 | 旧草稿覆盖新稿、重开已定标题都曾造成返工 |

## 三、不固化为通用规则的历史要求

| 历史事项 | 处理 |
| --- | --- |
| 标题里去掉“与”字 | 只适用于当时的题目，不禁止所有标题用“与” |
| 英文、数字与中文之间的空格 | 按当前项目设置；术语括注的写法另有规则 |
| 中文参考文献前置、编号不重排 | 当时的交付选择，不作为排序规则 |
| 去掉误差棒；结果图拆成四张 | 具体图的选择；保留“可读性优先”“说明统计依据”的原则 |
| 单美元 LaTeX 交给 MathType 转换 | 当时的工具链，不禁止 Office 公式 |
| 三线表、字号、页码、行距的具体数值 | 由模板决定，本Skill不猜数值；行距只有下文第四节一条例外 |
| 录音语速、视频页数 | 当次制作参数，不作为口播规范 |

## 四、后续确认

以下规则是在初版之后，于具体文档中确认并补入的。

- **公式逐式解释。**排法为“公式 A → 其中解释 A → 公式 B → 其中解释 B”；前式直接得到的简单性质（如权重之和为 1）并入文字说明，不单独成式。
- **自然分页。**Word 段落不自动启用“与下段同页”“段中不分页”，公式和释义也不额外加分页保护。早先“只隐藏标记、保留分页保护”的建议被这一条取代。
- **参考文献格式。**无模板要求时，按 GB/T 7714—2025 顺序编码制简化著录：不显示 DOI、网址和引用日期，正文引用用上标，文后两端对齐。英文著者姓氏只大写首字母、题名用句首大写、自动编号加悬挂缩进，这三项参照了同一课题组已提交的报告。会议文献在 `//` 前加一个半角空格，是为了让长串可以断行，明知与标准示例不同。
- **文献来源选择。**优先引用正式发表的论文和方法原始论文；赛题、数据说明和内部材料不为凑数量单列。
- **范围和横线。**表格外的数值和编号范围写“至”，概念连接按关系改写为“与”“和”，表格内不强制。
- **术语括注和正文字体。**首次出现写“中文（English Full Name, ABBR）”，外侧中文括号、内部英文逗号加一个半角空格；正文中文和中文标点用宋体。
- **符号正斜体。**起因是答辩 PPT 中同一符号在公式里是斜体、在解释文字里是正体。为避免前后不一致，定为一条固定规则。
- **引用图、图中字体、公式前冒号、行距、公式拆分。**来自一次帮他人修改开题报告：
  - “采用某模型（图8）[41]”这种夹在句中的括号，改为“如图8所示”，并全文统一；
  - 程序默认的无衬线字体让图“一看就是程序生成的”，改为宋体加 Times New Roman；
  - 独立公式前的引出句有的加冒号、有的不加，统一加上；
  - 公式转为 MathType 后行距忽大忽小，作者定下规则：套用以可读性为主的模板时（1.25 倍行距与 20 磅固定值视觉效果相近），直接用 20 磅；
  - 同时定下公式排法三条：尽量避免行内多行公式；行外的两行公式尽量拆开；拆开的两式是递进关系时，中间加“其中”等说明。

## 五、最终稿也不是无差别范本

最终提交稿用来识别最后采用的内容和结构，但其中仍有角色名称未完全统一、残留编辑过程语句、个别重复字、“其中”逐个解释运算符等问题。这些不作为正面样式。

## 六、试用

初版完成后，让一个只读本Skill的独立代理处理四个短请求：没有结果时改写抽象段落；根据两组均值写图后描述；把已录制台词原样整理成 Markdown；只修两段之间的衔接。代理均按规则完成，没有补造结果，也没有擅改台词。这说明核心规则能用于小任务，但不等于覆盖所有写作场景。后续修改依据实际使用中遇到的具体问题，不预先堆叠例外。
